## 📦 Variables

### What is a variable? What are the stack and heap, and the differences?

In Java, a **variable** is a reusable container used to store a specific value. Essentially, a variable behaves as if it were the value it contains.

```java
// primitive vs reference variable
int age = 30;
String name = "Phumrapee Chaowanapricha";
```
See: src/w02/basics/Variables.java

Variables are categorized into two main types:
*   **Primitive Data Types:** These store simple, direct values like integers, floating-point numbers (doubles), single characters (chars), and booleans (true/false). When declared as local variables inside a method, their values live directly in that method's stack frame. When declared as instance fields of an object, they're stored as part of that object on the Heap instead.
*   **Reference Data Types:** These are more complex, such as *Strings*, which represent a series of characters. Instead of storing the value itself, the variable stores a memory address that points to the data's location in the *Heap*.

In Java, the **Stack** and the **Heap** are two distinct areas of memory used to store different types of data.
*   **The Stack:** Each thread's stack is made of frames, and each frame's local variable array stores that method's local variables directly — this includes both primitive values and reference values (the pointer itself, not the object it points to). It is organized in a way that allows for efficient, direct access to these values.
*   **The Heap:** This area is used for **reference data types**, such as *Strings* or objects. Instead of storing the actual data, a reference variable on the *Stack* holds a **memory address** that points to the actual data stored in the *Heap*.

**Key Differences:**
1.  **Storage:** The *Stack* holds local variables for the currently executing methods — both primitive values and reference values (pointers) — while the *Heap* holds the actual objects (including their instance fields, even primitive ones) that those reference values point to.
2.  **Analogy:** You can think of a **primitive variable** (Stack) as someone handing you $10 directly. In contrast, a **reference variable** (Heap) is like receiving an IOU note; the note (on the Stack) tells you where to go, but the actual money is stored at the bank (the Heap).

## 🔀 Control Flow

### If statements

In *Java*, **if statements** are used to control the flow of a program by executing specific blocks of code only when a defined condition evaluates to **true**.

```java
// if / else
if (name.isEmpty()) {
    System.out.println("You didn't enter your name!");
} else {System.out.println("Hello " + name);}
```
See: src/w02/basics/IfStatementDemo.java

Key components include:
*   **If statement:** Performs a block of code if its condition is true. If the condition is false, the program simply skips that block.
*   **Else if clause:** Allows you to check additional conditions if the previous ones were false.
*   **Else statement:** Acts as a **default** block; it executes only if none of the preceding conditions in the chain are true.
*   **Comparison Operators:** When checking conditions (like comparing numbers), it is essential to use the **double equals sign (==)** for equality checks, rather than a single equals sign, which is reserved for assignment.
*   **Nested if statements:** You can place an if statement inside another if statement to evaluate more complex, multi-layered logic.

### Logical operators

In *Java*, **logical operators** allow you to check or modify multiple conditions within your code. They are essential for creating more complex decision-making structures.

The three primary logical operators are:

```java
// AND (&&) / OR (||) / NOT (!)
double temp = -20;
boolean isSunny = true;

if (temp <= 30 && temp >= 0 && isSunny) {
    System.out.println("The weather is good!");
} else if (temp <= 30 && temp >= 0 && !isSunny) {
    System.out.println("It's CLOUDY outside");
} else if (temp > 30 || temp < 0) {
    System.out.println("The weather is bad!!!");
}
```
See: src/w02/basics/LogicalOperatorsDemo.java

*   **AND (&&):** Requires that **all** linked conditions evaluate to *true*. If any condition is *false*, the entire expression becomes *false*.
*   **OR (||):** Returns *true* if **at least one** of the linked conditions is *true*. The entire expression is only *false* if all conditions are *false*.
*   **NOT (!):** This operator acts as an inverter. It takes a *true* value and makes it *false*, or a *false* value and makes it *true*. It is represented by an exclamation point.

## 🔁 Loops

### For Loop

A **for loop** in Java is a control flow statement used to execute a block of code a specific number of times. It is ideal for situations where you know the exact number of iterations beforehand.

```java
// basic for loop
for (int i = 0; i < 10; i++){
    System.out.println("Pizza");
}
```
See: src/w02/basics/ForLoopDemo.java

#### Structure

A standard for loop consists of three parts separated by semicolons:

```java
// init; condition; step
for (int i = start; i > 0; i--){
    System.out.println(i);
}
```
See: src/w02/basics/ForLoopDemo.java

1. **Initialization** — declaring and setting a counter variable (often `i` for index) to keep track of iterations.
2. **Condition** — a boolean expression that determines when the loop should stop. The code executes as long as this condition is true.
3. **Step (Update)** — an action performed after each iteration, typically incrementing or decrementing the counter.

```java
for (int i = 0; i < 10; i++) {
    // code to repeat
}
```

#### Key Concepts

- **Loop Control Variable** — the counter used to manage the loop's execution.
- **Enhanced for loop (for-each)** — a simplified version used to iterate through collections like **arrays** or **ArrayLists** without needing an index counter. Written as `for (dataType item : collection)`, it automatically processes every element.

### While Loop

A **while loop** in Java is a control flow statement used to repeatedly execute a block of code as long as a specified condition remains `true`. It is particularly useful when you don't know exactly how many times the loop needs to run.

```java
// while loop
while (name.isEmpty()) {
    System.out.print("Enter your name: ");
    name = scanner.nextLine();
}
```
See: src/w02/basics/WhileLoopDemo.java

#### Key Characteristics

```java
// do-while runs at least once
do {
    System.out.print("Enter a number between 1-10: ");
    number = scanner.nextInt();
} while (number < 1 || number > 10);
```
See: src/w02/basics/WhileLoopDemo.java

- **Condition Check** — the condition is checked at the start of each iteration. If the condition is false from the beginning, the code block inside will not execute at all.
- **Control** — you must ensure the condition is updated within the loop; otherwise, you risk creating an **infinite loop**, which can freeze the program.
- **Do-While Variation** — a `do-while` loop is a related structure that executes the code block *first* and then checks the condition at the end, ensuring the code runs at least once regardless of the condition.

## 🧩 OOP Basics

### What is OOP

Object-Oriented Programming is a paradigm based on "objects," which bundle data (fields/attributes) and code (methods/functions) together. Instead of focusing purely on logic or functions, OOP focuses on the objects being manipulated.

Core principles:
- **Classes and Objects** — a class is the blueprint, an object is the specific instance created from it.
- **Encapsulation** — grouping related data and methods into a single unit, restricting direct access to some components.
- **Inheritance** — a new class adopts properties and behaviors from an existing class.
- **Polymorphism** — objects can be treated as instances of their parent class rather than their actual class.
- **Abstraction** — hiding complex implementation details, showing only what's necessary.

These principles help build applications that are easier to scale, debug, and reuse.

### Class & Object

#### Class
A class is a **logical blueprint or template** for creating objects — a user-defined data type that groups related properties (instance variables) and functions (methods) together.

- Lets you bundle different types of data (e.g. an int for roll number, a String for name, a float for marks) into a single entity.
- Defines *what* properties and behaviors an object will have — the objects themselves hold the actual data.
- Does not occupy physical memory itself; it's just a definition.
- Convention: class names start with a capital letter.

#### Object
An object is the **physical manifestation** of a class — created from it using the `new` keyword, which triggers dynamic memory allocation.

- Holds specific data values (state) defined by the class's variables. E.g. if `Student` defines a name, one object might hold `"Kunal Kushwaha"`.
- Access properties/methods via the dot operator (`.`), which links the reference variable to the object's instance.
- When no longer needed, the Garbage Collector automatically clears its memory.

#### Class vs Object

| | Class | Object |
|---|---|---|
| Nature | Logical blueprint/template | Physical reality / instance |
| Memory | Doesn't occupy memory itself | Allocated actual memory (heap) at runtime via `new` |
| Defines | Structure — properties & behaviors | Holds actual data (state) |
| Sharing | One definition | Multiple objects share the same structure, each with its own unique state |

### Memory & Garbage Collection

#### Dynamic Memory Allocation
Memory for objects is allocated during **runtime**, not compile time.

- The `new` keyword tells the JVM to allocate space for an object in **heap memory** while the program runs.
- Unlike static allocation (often decided at compile time), dynamic allocation lets the program request memory based on current needs while executing.
- `new` returns a **reference** to the newly created object, used to access and manipulate its data.

#### Garbage Collection
Automatic process that identifies and removes objects no longer in use, preventing memory leaks — unlike C++, where developers must free memory manually.

- Java automatically destroys objects once they're no longer reachable by any reference variable.
- You can't force destruction at a precise moment, but the `finalize()` method lets you define cleanup logic that runs just before the collector removes an object.
- Because it runs automatically in the background, timing isn't predictable/controllable — a key difference from manual memory management.

### Constructors

A **constructor** is a special method that initializes an object when it's created with `new`.

- **Purpose:** ensures an object is set up with initial values (e.g. name, roll number, marks) at the moment of instantiation.
- **Default constructor:** if you don't define one explicitly, Java provides a no-argument constructor that initializes variables to their default values (`0`, `0.0`, `null`, etc).
- **Custom constructors:** define your own to accept arguments and pass specific values at creation time.
- **Constructor overloading:** a class can have multiple constructors with different parameter lists, for flexible initialization.
- **`this` keyword:** inside a constructor, `this` refers to the current object being created — commonly used to disambiguate instance variables from constructor parameters that share the same name.

#### Constructor chaining (`this()`)
You can call one constructor from another in the same class using `this()`.

- **Syntax:** `this(...)` followed by the required arguments.
- **Purpose:** avoids code duplication — one constructor holds the core init logic, others just pass default/custom values into it (e.g. assigning a default roll number if the user doesn't provide one).
- **Mechanism:** calling `this()` runs the code inside the target constructor, so the object gets initialized per that constructor's logic.

### Other Keywords

#### Wrapper Classes
Represent primitive types (`int`, `char`, `float`, etc.) as **objects**.

- Every primitive has a corresponding wrapper class (`Integer` for `int`, `Character` for `char`, ...) — needed anywhere primitives must behave as objects, e.g. in Collections.
- Provide extra methods/fields beyond what raw primitives offer.
- **Trade-off:** more memory overhead than primitives since they're objects — Java defaults to primitives for standard operations and only reaches for wrappers when the object-oriented behavior is actually needed.

#### `final` Keyword
Restricts reassignment/modification.

- A `final` variable's value can't change once initialized.
- Should generally be initialized at the point of declaration.
- On an object reference: the reference itself can't be pointed at a different object, but the object's *internal state* can still be modified.
- Also applies to classes (prevents inheritance) and methods (prevents overriding).

## 🔒 Encapsulation

Encapsulation is one of the four pillars of OOP. It means keeping an object's data (its state/attributes) inside the object itself — like medication in a capsule — so the outside world only interacts with it through controlled interfaces.

### The problem with public fields
Allowing direct access to fields (e.g. `name`, `age`) invites bad practices, like assigning invalid values (a negative age) — there's no validation layer to stop it.

### Getters and setters
To encapsulate properly:
- Mark fields `private`.
- Use `public` **setter** methods to validate input before it's assigned.
- Use `public` **getter** methods to safely retrieve data.

### Handling invalid input in a setter
Two common strategies:
1. **Set a default/safe value** — correct the input to a minimum or maximum allowed constant instead of rejecting it outright.
2. **Throw an exception** — stop execution by throwing a `RuntimeException` to alert the caller that invalid data was passed in.

### IDE tooling
IntelliJ can auto-generate getters/setters and refactor fields to `private`, speeding up the encapsulation process.
